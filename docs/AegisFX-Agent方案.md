## 0.5 第 4 阶段的定位与问题重述（2026-09-28）

### 定位

> 本项目不是论文数值结果的严格复现。由于原论文完整实验脚本及部分实现细节不可
> 获得，本项目以公开资源为基础建立**可运行重构**，并在统一的**时间切分、as-of
> 检索和异常收益评测协议**下开展独立的方法扩展。

允许修改算法本身（异常收益、检索排序、冲突度量、置信度、风险控制），
但**必须保留公平的对照算法**——不能为了让新方法好看而改基线或评测协议。

### 研究问题（RQ1 已重述）

> 普通语义检索、固定金融重排序和语义约束自适应重排序，在**主题相关性**与
> **离线结果有用性**之间表现出怎样的权衡？

原来写的是「普通语义相似度是否足以找到有效历史事件」，太宽泛——
「有效」到底指什么，之前没说清。现在拆成两个可测的口径，见 §9.3。

**不预设 E3 一定优于 E1/E2。** 第 4 阶段的实测结果是 E3 在离线结果有用性上
**没有**优于 E1（见进度文档），这个结论如实保留。

### 一条失败实验的记录

第 3 阶段试过让大模型给 0–3 整体相关性评分当第二标注员。
**它未表现出可接受的一致性**，因此不作为正式评价依据：

- 给分几乎是均分（3 分 105 条 / 2 分 101 条 / 1 分 105 条 / 0 分 15 条）；
- 对「美国财政部制裁中国公司」与「美商务部将 35 家中国企业加入实体清单」
  这种同族同发起方同情感的两条候选，给了 3 分和 2 分。

要救的话得把整体判断**拆成三个可核查的子问题**（是否同事件族 / 是否同发起方 /
政策方向是否相同），再由程序合成等级，而不是让模型直接给模糊的总分。
本阶段不做。

### 1.3 一条重要的实测结论：方向基准会吃掉结论

20 日 USD/CNY 变动，事件样本上的方向基准：

| 区间 | 事件数 | P(USD/CNY 上涨) |
|---|---:|---:|
| 2017–2019 | 141 | 0.496 |
| 2020–2022 | 144 | 0.403 |
| **2023–2024（评测期）** | **155** | **0.697** |
| 2023–2024 全部交易日（无条件） | 465 | 0.649 |

在评测期，"一律猜人民币贬值"就有 **69.7%** 的方向准确率（n=155，已剔除
前瞻收益算不出来的 5 条）。
**所有方向准确率必须与这个基准并列报**，否则 65% 这个数字毫无意义。

信号确实存在（美国对中国加征关税后 20 日平均 +0.68%，放宽关税 −0.12%，方向符合直觉），
但 20 日标准差是 1.43%，信号噪声比只有 0.09。**所以项目重心不能放在提精度上**，
要放在检索质量、冲突诊断、共形覆盖率、执行闸门这四件事上。

另一个连带风险：检索池（2020–2022 基准 0.403）与评测期（0.697）方向相反。
**从历史证据出发推理会系统性预测错方向。** 这是本项目最大的风险，也是共形区间
和执行闸门存在的理由——如果最后证明"普通 RAG 因制度漂移反而变差"，
那本身就是够格的结论。

> **第 2 周实测修正（2026-09-27）**：换成异常收益口径之后，评测期基准是
> **55.6%**，不是这里原先估计的"五成上下"。
>
> 改善是真的（70.9% → 55.6%，按合并后 156 条评测事件算），但**没有掉到 50%**：
> 2023–2024 的人民币贬值还有美元以外的驱动（利差、资本流动、增长预期），
> 异常收益没有把这些扣掉。所以方向预测仍然比抛硬币难，
> 凡报方向准确率都要和 **55.6%** 这个数并列。

## 3. 人机混合输入通道

**这是本次新增的重点。** 系统在任何模式下都不依赖实时新闻源，人工投递是一等入口。

### 3.1 三个入口，一个队列

| 入口 | 用法 | 场景 |
|---|---|---|
| Streamlit 输入框 | 粘贴消息文本 + 可选 URL，点提交 | 演示、临时补录 |
| CLI | `python scripts/ingest_event.py --text "..." --url "..."` | 脚本化、批量 |
| 监视目录 | 把 `.json` 丢进 `data/inbox/`，系统自动读取 | 半自动流水线 |

三者都写进同一个 `RawEvent` 队列，之后的处理路径完全一致。

### 3.2 RawEvent Schema

```text
raw_id
ingested_at              # 进入系统的时刻
ingested_by              # human / file / rss / api
text                     # 消息原文
source_url               # 可空
source_name              # 可空
source_published_at      # 可空；缺失时用 ingested_at 占位并标为推测
verified                 # bool，人工投递默认 False
```

### 3.3 四个时间戳（缺了这个就没法证明系统"快"）

每个事件全流程保存：

```text
source_published_at      # 消息发布
agent_detected_at        # 系统发现（人工投递时 = ingested_at）
signal_generated_at      # 产出信号
paper_order_submitted_at # 模拟下单

Latency = paper_order_submitted_at − source_published_at
```

**人工投递的消息，`source_published_at` 由投递人填**；不填就用 `ingested_at` 并标记为
推测值。延迟统计里要区分这两类，否则"人工补录的 8 小时延迟"会污染真实延迟指标。

### 3.4 未验证消息的处理（与第 4.7 节的闸门自动咬合）

```text
字段缺失 / JSON 不合法 / verified = False
    → 研究层照常跑：解析、检索、冲突、共形区间、解释文本
    → 执行层自动 BLOCKED，原因写明 "source_unverified"
```

这条设计刚好把"人能随时喂消息"和"不能拿小道消息去下单"两件事同时满足，
不需要额外的开关。

### 3.5 新消息超出数据覆盖期怎么处理

`Data.xlsx` 的日频行情到 **2024-12-31** 为止。2025 年以后的事件在**论文那份数据**里
没有标签。**但第 1 周的探测确认 FRED 的 `DEXCHUS` 一直更新到当天**
（探测时是 2026-09-18，6.6975），所以第 2 周接上它之后，
2025 年之后的事件也能拿到标签，`pending` 只是短期状态，不是死胡同。

- 检索照常（只用更早的事件，as-of 天然成立）；
- 方向、共形区间照常输出；
- `abret` 标记为 **`pending`**，不进任何评测统计；
- 演示页显示「待观察」，并记录 `label_due_at = 事件日 + h 天`，到期后能自动补标签；
- **新事件绝不能进检索池参与历史评测**。

## 4. 算法

### 4.1 事件解析

大模型把消息转成固定 JSON：

```json
{
  "event_type": "us_tariff_increase",
  "initiating_side": "US",
  "target_side": "CN",
  "sentiment": "negative",
  "event_stage": "official_announcement",
  "source_published_at": "2026-09-26T14:30:00Z"
}
```

事件类型必须落在枚举内，**枚举可扩展**：历史 16 类之外的新消息（美联储、人行、
外汇管理政策）归入 `other` 并保留原文，不强行归类。

| 中文类型 | snake_case |
|---|---|
| 中美对话 | `bilateral_dialogue` |
| 美国对中国加征关税 | `us_tariff_increase` |
| 美国对中国放宽关税政策 | `us_tariff_relief` |
| 美国对中国企业的限制 | `us_restrict_cn_firms` |
| 美国对中国企业降低限制 | `us_ease_restrictions_cn_firms` |
| 美国对中国发起诉讼或调查 | `us_litigation_cn` |
| 美国指责中国 | `us_criticize_cn` |
| 美国将中国列为汇率操纵国 | `us_designate_cn_fx_manipulator` |
| 美国将中国从汇率操纵名单剔除 | `us_remove_cn_fx_manipulator` |
| 中国加大对美国采购 | `cn_increase_purchases` |
| 中国对美国加征关税 | `cn_tariff_increase` |
| 中国对美国放宽关税政策 | `cn_tariff_relief` |
| 中国对美国企业的限制 | `cn_restrict_us_firms` |
| 中国对美国企业降低限制 | `cn_ease_restrictions_us_firms` |
| 中国对美国发起诉讼或调查 | `cn_litigation_us` |
| 中国指责美国 | `cn_criticize_us` |

`event_stage` 由大模型推断，**只用于展示**，不作为确定性检索特征——表里没有这个字段，
可靠来源也没有，把它当检索依据等于让大模型决定检索结果。

### 4.2 异常收益：市场模型

比简单扣除历史均值更有研究价值，因为预测的是**事件带来的额外影响**，不是美元整体趋势：

$$r_{FX,t} = \alpha + \beta_1 r_{DXY,t} + \beta_2 \Delta Spread_t + \varepsilon_t$$

$$AR_{t,h} = r_{FX,t,h} - \hat r_{FX,t,h}$$

样本不足时降级为同 $h$ 的均值调整：

$$AR_{t,h} = r_{t,t+h} - \operatorname{mean}(r_{j,j+h})$$

**量纲必须一致**——右边是同样的 $h$ 日收益，不是日收益。

> **第 2 周实测修正（2026-09-27）**：上面这个式子**按日频估是错的**，已改为
> **在与事件窗口相同的 h 日尺度上估**，估计窗口取 **250** 个交易日。
>
> 原因是人民币管理浮动——中间价把大部分美元波动吸收掉，日频上 USD/CNY 与
> 美元指数的相关性只有 0.24。在这个信噪比下估出的 β̂ 噪声很大，
> 逐日算残差再累加，20 日异常收益的标准差**反而比原始收益大 7.8%**。
> 拉到 20 日尺度估，相关性升到 0.59，β̂ 才稳得住（0.13 → 0.44），
> 跨事件标准差降 9.8%。
>
> 估计窗口 120 日也不行：20 日尺度上只有约 6 个有效独立观测。
> 改成 250 日之后三个尺度都变好。详见 `src/aegisfx/data/abnormal.py`。

### 4.3 As-of 检索

对时间为 $t$ 的事件，检索池只含 $date_i < t$ 的事件。

**关键细节**：$t$ 用 **`source_published_at`（当时可知时间）**，不是 `effective_time`。
政策生效时间可能在未来，用它截断等于提前使用未来信息。

$$S_i = 0.40 S_i^{sem} + 0.25 S_i^{event} + 0.25 S_i^{market} + 0.10 S_i^{time}$$

| 项 | 内容 |
|---|---|
| $S^{sem}$ | FAISS 余弦相似度 |
| $S^{event}$ | 事件类型相同 + 发起方相同 + 情感极性的加权和 |
| $S^{market}$ | 1 年期利差、美元指数、20 日已实现波动率、外储 3 个月变化率的高斯核距离；标准化参数只用事件日之前的数据拟合 |
| $S^{time}$ | $e^{-\lambda \Delta t}$，**只做权重，不做过滤**（历史重大政策不该因久远被删） |

权重**先验固定，不在评测集上调**。

### 4.4 双冲突度量

$$CI = 1 - \frac{|W_{up} - W_{down}|}{W_{up} + W_{down} + \epsilon},
\qquad W_{up} = \sum_{i: AR_i > 0} S_i$$

$$D = \sqrt{\frac{\sum_i S_i (AR_i - \widehat{AR})^2}{\sum_i S_i}},
\qquad \widehat{AR} = \frac{\sum_i S_i AR_i}{\sum_i S_i}$$

两项交叉解读：

| | 幅度离散低 | 幅度离散高 |
|---|---|---|
| **方向分歧低** | 证据一致 → 高置信 | 同向但幅度差得多 → 中等置信 |
| **方向分歧高** | **噪声**（正负都在 ±0.1% 级别） | **真冲突** → 最低置信 |

只有 CI 的话，左下和右下分不开。

### 4.5 加权方向预测

$$\widehat{AR} = \frac{\sum_i S_i AR_i}{\sum_i S_i},
\qquad P(up) = \frac{W_{up}}{W_{up} + W_{down} + \epsilon}$$

无论证据冲突与否，研究层始终输出方向、幅度、原始方向概率。
**原始方向概率不是校准后的概率**，校准交给共形区间，两者不要混用。

### 4.6 Walk-Forward 共形预测

对第 $t$ 个事件，用 $t$ 之前所有事件的残差 $R_j = |AR_j - \widehat{AR}_j|$ 构造区间：

$$PI_{1-\alpha} = [\widehat{AR} - q_{1-\alpha},\ \widehat{AR} + q_{1-\alpha}]$$

首版输出 80% 和 90% 两档。

**必须处理的一件事**：可交换性假设在本数据上不成立（第 1.3 节：2020–2022 与
2023–2024 方向相反）。naive split-conformal 会失配。

做法：

1. 残差分位数用**时间衰减加权**：$e^{-\lambda \Delta t}$ 作权重算加权分位数；
2. **显式报告实际覆盖率 vs 名义覆盖率**，分时期（2017–19 / 2020–22 / 2023–24）各报一次；
3. 若 2023–2024 覆盖率明显低于 80%，改用 **ACI（Adaptive Conformal Inference）**
   在线调整 $\alpha_t$，并把失配本身写成一条结论。

这一步的诊断表，很可能是整个项目最有信息量的产出。

### 4.7 执行闸门

```python
allow_execution = (
    source_verified
    and parse_ok
    and data_is_fresh
    and no_future_leakage
    and conflict_index < conflict_limit
    and interval_width < width_limit
    and spread < spread_limit
    and daily_loss_not_reached
    and drawdown_not_reached
)
```

**输出必须列出全部检查项及其通过状态**，不只给一个布尔值，方便事后审计：

```text
预测方向：USD/CNY 上涨
异常收益预测：+0.18%
80% 共形区间：[−0.31%, +0.72%]
执行状态：BLOCKED
  source_verified      ✗  人工投递，未提供来源链接
  interval_width       ✗  区间跨 0
  conflict_index       ✗  0.78 > 0.65
  data_is_fresh        ✓
  ...
```

**阈值来源**：`conflict_limit` 和 `width_limit` 从校准集的分位数推导
（例如取校准集上 `width` 的 75% 分位），不要手调。手调等于又加两个自由度。

### 5.2 模拟盈亏的两个口径

模拟盈亏很容易被趋势主导：2023–2024 人民币单边贬值，只要做多 USD/CNY 就赚，
跟事件证据没关系。所以两个口径并列报：

| 口径 | 定义 | 回答什么 |
|---|---|---|
| 原始盈亏 | 持仓期原始收益 − 点差成本 | 真实交易结果 |
| **漂移调整后盈亏** | 持仓期异常收益 − 点差成本 | **闸门拦下的是不是事件相关的亏损** |

只看原始盈亏，会把"闸门刚好躲过了趋势"误当成"闸门有效"。

## 8. 风险 Agent

**不能调用大模型决定是否止损**，全部走确定性规则。至少覆盖：

单次最大风险预算、总仓位上限、单日亏损上限、最大回撤上限、连续亏损暂停、
点差异常暂停、行情过期暂停、消息来源未验证暂停、共形区间跨零禁止执行、
高冲突禁止执行、重复订单拦截、API 故障禁止下单、人工 Kill Switch。

止损只是其中一层。**快速行情下止损可能产生滑点，不能保证按目标价成交**，
这一点要写在页 3 上，不要让人误以为止损是硬保证。

系统只允许四种模式：

```text
research / backtest / shadow / paper
```

**仓库默认不得进入任何真实交易模式。** 境内个人进行外汇交易存在明确的渠道合规限制。

## 9. 实验设计

### 9.1 预测层（比检索与冲突，不涉及执行）

> **第 4 阶段统一命名（2026-09-28）。** 代号改过一轮，以这张表为准：
>
> | 代号 | 方法 | 备注 |
> |---|---|---|
> | `B0` | 原仓库可运行重构 | **只说明项目起点，不声称复现论文数值** |
> | `E1-semantic` | 纯语义检索 | 候选集 = 整个 as-of 池，只按语义排 |
> | `E2-fixed-reranker` | 固定权重金融重排序 | 同一候选集，四项加权和 |
> | `E3-adaptive-conflict-rag` | 语义约束自适应重排序 | 候选集**先**收窄到语义 Top-20 |
>
> E1、E2 只修过程序错误，**没有根据结果重新调权重**；E3 是独立的新算法。
> 三路共用同一个 as-of 候选池与评测口径。
>
> E3 的分数式：$S_i = S_i^{sem01}(1+\alpha_q F_i)$，
> $F_i = 0.45S_i^{event} + 0.40S_i^{market} + 0.15S_i^{time}$，
> $\alpha_q = 0.5 \cdot \mathrm{clip}((p_q-0.5)/0.5, 0, 1)$，
> $p_q$ 是语义 Top-5 里与查询同族的比例。**α 是查询级自适应的**：
> 语义结果本身很散时 α 自动压到 0，不让金融变量把主题带偏。

| 组 | 方法 |
|---|---|
| **E0** | 扩展窗口历史 AR 均值，无检索 |
| E1 | 纯语义 kNN |
| E2 | 金融状态重排序 kNN |
| E3 | 冲突感知 kNN（双冲突度量 + 加权） |

E0 与 E1 的差别是「用全部历史 vs 只用相似历史」，是一次干净消融。

**补一条参照线**（不进主表）：**LLM 直接判断、不给任何历史案例**。
成本只有 156 次调用，但它回答的是"RAG 相对大模型先验到底有没有用"，
这是审稿人一定会问的。

### 9.2 交易层（E3 vs E4，比执行）

| 组 | 方法 |
|---|---|
| E3 | 冲突感知，**不做闸门**（有信号就下） |
| **E4** | 冲突感知 + 共形区间 + 执行闸门 |

E3 与 E4 的预测完全相同，只有下单与否不同，所以指标体系要换：

- 拒绝交易的比例；
- 被拒绝交易的收益分布（**闸门拦下的是亏损还是利润**）；
- 通过闸门的交易在原始 / 漂移调整两个口径下的盈亏；
- 最大回撤对比；
- 共形区间覆盖率（E4 独有）。

### 9.3 指标与必报基准

**检索质量（主贡献）**：Precision@K、Recall@K、NDCG@K（K = 3/5/10），
配 20 条查询 × Top-10 的**人工相关性标注**。

> **第 3 周实测修正（2026-09-28）**：加了第二套口径，因为第一套不够用。
>
> | NDCG@5 | E1 纯语义 | E2 金融重排序 |
> |---|---:|---:|
> | 主题相关性（人工/大模型） | 0.879 | 0.699 |
> | **结果有用性**（客观口径） | 0.459 | **0.501** |
>
> 两套方向相反，因为问的不是同一件事：前者问「像不像先例」，后者问
> 「这条先例的汇率反应能不能说明当前事件会怎样」——后者才是 RAG 要的。
> 客观口径用事件库的异常收益标签定义相关性（见
> `scripts/evaluate_retrieval.py`），不花人工时间。
>
> **两套都要报。** 只报前者会得出「重排序有害」，只报后者会得出「重排序有效」。
> 而且客观口径下 20 条查询是 **9:9 平手**，均值的小幅优势来自个别查询的大幅
> 改善被另几条的大幅恶化抵掉——「重排序有用」在第 3 周还立不住。
>
> **大模型第二标注员已放弃**：给分近乎均分（105/101/105/15），
> 且对同族同发起方同情感的两条候选给出不同分。要用得把它拆成三个可核查的
> 子问题再由程序合成等级，不能让它直接给模糊的总分。

**预测质量**：方向准确率（异常收益口径）、MAE、MAPE。
**方向准确率必须与多数类基准（评测期 69.7%）并列。**

**不确定性质量**：共形实际覆盖率 vs 名义覆盖率（80% / 90%），分时期各报；
Brier Score、ECE、可靠性曲线作为补充。

**执行质量**：见 9.2。

**解释质量**：人工评 10–20 条，检查是否引用真实证据 id、是否给出正反两面、
有没有把升贬值说反、有无无依据结论；解释文本里的数字与程序结果的一致性**用程序自动校验**。

### 9.4 统计推断

事件成簇（2018–2019 密集），20 日窗口大量重叠，**标签不独立**。
不要用朴素 t 检验，用 **block bootstrap**（按月分块）报置信区间。

- 约 400 条结构化事件 + 异常收益 + 市场状态；
- 可重复建立的 FAISS 事件索引；
- As-of 检索协议（含越界断言）；
- 双冲突度量；
- Walk-Forward 共形预测（含覆盖率诊断）；
- 人机混合输入通道（三种入口）；
- 执行闸门 + 风险 Agent（13 条规则）；
- E0–E4 实验 + 两条参照线（多数类基准、LLM 无检索）；
- 三页 Streamlit 系统，一条命令启动；
- 一条命令复现实验；
- 技术报告、PPT、演示视频。

### 最低成功线（不要求预测精度提升）

严谨证明下列任意一项即可：

1. 金融重排序改善了历史事件检索质量（**最有把握**）；
2. 高冲突事件的预测误差确实更大；
3. 共形区间覆盖率达标（或**明确报告在制度漂移下失配**，并说明修正效果）；
4. 执行闸门减少了漂移调整口径下的大额亏损（或明确报告闸门无效）；
5. 普通 RAG 在制度漂移下未带来稳定增益，并解释原因。

### 必报项

- 方向准确率与多数类基准并列；
- 所有指标给 block bootstrap 置信区间；
- 共形区间报告实际覆盖率，不只报宽度；
- 检索质量说明人工标注口径与一致率；
- 模拟盈亏给两个口径。

## 附：术语口径（全文统一）

| 说法 | 含义 |

| 异常收益 / AR | 事件窗口收益 − 市场模型（DXY、利差）预测的收益 |
