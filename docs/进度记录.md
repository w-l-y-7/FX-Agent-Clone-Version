### 2. 汇率自身的价格：论文 Table 4 里有，公开代码里没有

**Table 4「时序特征信息表」的第一行就是 USD/CNY 本身**（feature sample 6.8689，
即 2017-02-28 的收盘价）。也就是说论文的时序特征集含汇率价格，模型因此有能力
学到"价格几乎不变"这条规律——这正是它能跑赢朴素基准的关键。

本项目补全时把 USD/CNY 当目标列排除了，代价很大：模型看不见价格，就只能预测
训练区间的均值，**结构上不可能跑赢朴素基准**。

现在五个模型都加了 `INCLUDE_PRICE_HISTORY` 开关并**默认打开**。实测差距：

- TimesNet：RMSE 0.3901（不含价格）→ **0.2035**（含价格），差一半。

### 3. 论文公式 (2) 与 Table 6 对不上

公式 (2) 写的是"用所有候选特征得分的最大最小值做归一化"，但 Table 6 那五行的
分数（100 / 92 / 90 / 80 / 8）**只有按理论满分 5.0 归一化才算得出来**；
按公式字面写法会算出 91 / 89 / 78 / 0。

本项目默认用能复现论文的 `theoretical` 模式，`--normalization batch` 可切到
字面写法对比。**这一条仍然需要作者确认以哪个为准。**

### 4. 底座模型 R1 用不了 function calling

论文的底座是 DeepSeek-R1（671B）。但 R1 的思考模式**不支持 `tool_choice`**，
而 DA 的结构化打分正是靠它。实测：

| 模型 | `function_calling` | `json_mode` |
|---|---|---|
| `deepseek-chat` | 通过 | 通过 |
| `deepseek-reasoner`（R1） | **400：Thinking mode does not support this tool_choice** | 通过 |

代码现在会按模型名自动切换实现方式，`DEEPSEEK_MODEL="deepseek-reasoner"` 即可
按论文口径跑。DA 的磁盘缓存键里也加了模型名，避免换模型后静默复用旧分数。

## 三、跑出来的数（本机，CPU）

预测步长 HORIZON=20，序列长度 30，测试集比例 0.2，特征集 `pa1_pa2_da`。

| 模型 | 含价格历史 | 本机 RMSE | 本机 MAPE | 论文 RMSE | 论文 MAPE |
|---|---|---|---|---|---|
| Transformer | 是 | 0.3238 | 3.8719% | 0.0566 | 0.6532% |
| LSTM + Attention | 是 | 0.2667 | 3.4820% | 0.0599 | 0.7205% |
| RNN | 是 | 0.2506 | 3.2873% | 0.0650 | 0.8121% |
| TFT | 是 | 0.3721 | 4.9051% | 0.0330 | 0.3427% |
| TimesNet | 是 | **0.2035** | **2.6077%** | 0.0436 | 0.4874% |
| **朴素基准** | — | **0.0813** | **0.8438%** | — | — |

`RNN` 和 `LSTM + Attention` 用的是**作者被删除实现里的网络结构**（见下面
「交付边界」）：RNN 没有输入投影、用 `relu` 而非 `tanh`；LSTM + Attention 的
注意力是与一个可学习 vector 做点积。换结构后两个模型都变好了
（RNN 0.2716 → 0.2506，LSTM+Att 0.3120 → 0.2667）。

（TFT 那一行的朴素基准是 0.0853，因为它切分的是样本列表而不是原始行，测试段
起点略有不同。另外 `Transformer` / `TimesNet` 在加价格开关**之前**、即不含价格的
旧口径下分别是 0.2208 / 0.3901，可以看第六节「注意四」。）

**三点如实说明：**

1. **五个模型全都没跑赢朴素基准（0.0813），而且差得不小**（最好的 TimesNet
   也差 2.5 倍）。论文里它们分别赢 30%~60%。这个差距就是"重构"和"还原"的差距：
   论文的批次大小、优化器、学习率调度、HORIZON、切分比例、目标变量口径全都不知道。
2. **TFT 是最差的，而论文里它是最好的。** 训练损失 0.0139、测试损失 0.5143
   （差 37 倍）。预测曲线显示 P50 跟住了局部形状但整体系统性偏低。`TFT.py` 的
   `VariableSelectionNetwork` 是从零重写的（原实现 forward 就是坏的），
   **这是最可疑的一处，属于待查项，不是结论。**
3. **Transformer 加价格反而变差（0.2208 → 0.3238），先别下结论**：五个模型都
   没固定随机种子，同配置跑两次结果就不一样。要判定得先固定种子再各跑几次。

TimesNet 的改善（0.3901 → 0.2035，接近减半）方向上是符合预期的——含价格的
输入理论上应该有明显帮助。但 TFT 和 Transformer 的表现和这个预期不一致，
这两处都还没查清。

### 不阻塞交付、但值得继续做的三件事

这几件都**不影响项目能用**，是精度层面的深挖：

1. **给五个模型固定随机种子**（`torch.manual_seed` / `np.random.seed`），
   再各跑 3 次。现在同一个配置两次结果不一样，上面那张表里的任意两行都
   可能只是种子噪声。**做任何模型间比较之前先做这一步。**
2. **查 TFT 为什么最差。** 起点是 `VariableSelectionNetwork`（从零重写的部分）
   和变量选择权重：`forward` 支持 `return_weights=True`，把三个 VSN 的权重打出来
   看 `close` 占了多少，就知道模型有没有用上价格。
3. **查 Transformer 加价格为什么变差。** 先做第 1 件，再判断这是真实现象还是噪声。
