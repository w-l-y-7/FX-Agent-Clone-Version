这份文档是补充的，不是论文作者原来写在 `README.md` 里的内容。看不懂英文的话看这份就行。

## 一、这个项目在做什么

用四个智能体（LangGraph 编排）预测 **USD/CNY 汇率**：

```
Planning 定计划 → Perception 取数据 → Decision 挑特征 → Forecasting 出预测
                                          ↑                    ↑
                                    论文的核心创新点      调参 + 可解释性
```

**Decision 智能体（DA）** 是整篇论文最新颖的部分。它做的事情是：对每一个候选
特征，去知识库里检索证据，然后让大模型依据证据给这个特征打三个分（相关性、
支持度、实用性），加权算总分，达到 80 分才采纳。分数不够时不会直接淘汰，
而是换个更精准的问题重新检索，最多重试 3 轮。

这个设计的妙处在于：**特征筛选的依据可以逐条追溯**。跑完之后你能看到
"为什么选了油价、为什么扔了 CPI"，每一条都能指到知识库里的具体段落。

**Forecasting 智能体（FA）** 负责最后一步：用 Optuna 搜超参、训练模型、
再用 SHAP 把"哪些特征在推动预测"拆出来，最后让大模型把这一堆数字翻译成
一段人话。

## 二、第一次跑，三步

```powershell
# 第 1 步：确认 .env 里有 DEEPSEEK_API_KEY（密钥不要提交到 git）

# 第 2 步：建知识库索引（第一次要下载 95MB 的向量模型，之后几秒）
.\venv\Scripts\python.exe scripts\build_knowledge_base.py

# 第 3 步：跑完整流程。先用 --limit 8 试水，约 3 分钟
.\venv\Scripts\python.exe main.py --limit 8
```

确认没问题后，去掉 `--limit` 跑完整的 32 个候选特征（第一次约 15 分钟）：

```powershell
.\venv\Scripts\python.exe main.py
```

**重复跑很快。** 每次调用的结果都会存到 `.cache/da/`，同样的特征第二次跑
不花钱也不花时间。只有改了提示词才会重新调 API。

## 三、常用命令

### 主流程

| 命令 | 作用 |
|---|---|
| `python main.py --limit 8` | 只评前 8 个候选特征，快速验证 |
| `python main.py` | 跑完整候选集（32 个） |
| `python main.py --no-cache` | 忽略缓存，看真实耗时 |
| `python main.py --optimize` | 预测换用 Optuna 调参 + SHAP 解释那套服务 |
| `python main.py --optimize --trials 60` | 同上，但 Optuna 多搜几组超参 |
| `python main.py --normalization batch` | 改用论文公式(2)的字面写法归一化 |
| `python main.py --live` | 换回原作者的实时数据线（AKShare + Firecrawl） |

### 单独跑的脚本

| 命令 | 作用 |
|---|---|
| `python scripts/run_da_selection.py` | 只跑 DA 的特征筛选，不跑预测 |
| `python scripts/build_knowledge_base.py --query "..."` | 建索引并试检索一条 |
| `python scripts/verify_pa2_aggregation.py` | 复现 PA2 的事件聚合，和论文数据逐列对照 |
| `python scripts/verify_traditional_baseline.py` | 复现论文 §4.4 的传统特征工程基线，和 Table 8 对照 |

### 深度模型

| 命令 | 作用 |
|---|---|
| `python src\legacy_models\Transformer.py` | 论文的 Transformer，约 5 分钟（本机实测 4 分钟） |
| `python src\legacy_models\Timesnet.py` | 论文的 TimesNet，约 1 分钟 |
| `python src\legacy_models\RNN.py` | 论文的 RNN，约 3 分钟 |
| `python src\legacy_models\LSTM_Attention.py` | 论文的 LSTM + Attention，约 3 分钟 |
| `python src\legacy_models\TFT.py` | 论文的 TFT，**约 25~30 分钟**（模型本身慢，见第六节） |

**这五个就是论文 Table 7 评的全部模型**，缺的 RNN 和 LSTM+Attention 是补的
（原公开代码里只有另外三个的模板，而且那三个也只是模板，见第六节「注意五」）。

五个文件里都有 `FEATURE_SET` 和 `INCLUDE_PRICE_HISTORY` 两个开关，想按论文的
不同口径跑就改它们——`FEATURE_SET` 对应论文 Table 7 消融实验的三行，
`INCLUDE_PRICE_HISTORY` 对应输入含不含汇率自身价格（见第六节「注意三」）。
**两个开关不同，跑出来的数不能直接比。**

### 关于 `--normalization` 这个开关

论文公式 (2) 写的是"用所有候选特征得分的最大最小值做归一化"，但论文
Table 6 里那五行分数（100 / 92 / 90 / 80 / 8）**只有按理论满分 5.0 归一化
才算得出来**。按论文的字面写法会算出 91 / 89 / 78 / 0，对不上。

默认用 `theoretical`（能复现论文的那套），想知道差别可以跑一次 `batch` 对比。
**这个问题值得拿去问论文作者。**

## 六、跑深度模型

五个模型都用 `Data.xlsx` 的同一份数据、同一套切分，指标口径一致，可以直接对比。

### 注意一：预测步长（`HORIZON`）

五个文件里都有一个 `HORIZON` 参数，默认 **20**（交易日）。
论文没有写明这个值，但可以反推出它大概是多少。

USD/CNY 近似随机游走，日频变动的标准差约 0.017。按 h 天预测时，
"假设价格不变"这条朴素基准的 RMSE 大致是 `0.017 × √h`。本项目实测：

| 预测步长 | 朴素基准 RMSE | 论文 Transformer 的 RMSE |
|---|---|---|
| 1 天 | 0.0225 | 0.0566（**比基准差 2.5 倍**） |
| 5 天 | 0.0379 | 同上 |
| 20 天 | 0.0813 | 0.0566（**比基准好 30%**） |

**只有多步预测的设定下，论文报的数字才讲得通。** 如果按 1 天跑，你会发现
自己的模型怎么也赢不了那条"什么都不做"的基准——那不是代码写错了，
是设定对不上。这个值值得跟论文作者确认。

### 注意二：论文自己的 PA1 配置也跑不赢随机游走

论文 Table 7 里 Transformer 在"只用 PA1 七个宏观特征"这一行是 **RMSE 0.0936**，
而 20 天步长的朴素基准是 **0.0813**——**论文自己的这个配置也是输给随机游走的**。

它真正的提升来自 PA2 和 DA（0.0936 → 0.0737 → 0.0566）。这恰恰是论文的核心
论点，也说明 DA 不是装饰。想看这条链，把文件里的 `FEATURE_SET` 依次改成
`'pa1'` / `'pa1_pa2'` / `'pa1_pa2_da'` 各跑一次即可。

**不过这里有一处拧着的地方值得注意**：论文 Table 4 把 USD/CNY 本身列进了时序
特征表（见注意三），可如果 PA1 的输入真的含滞后汇率，那一行"只跑 PA1"的结果
按理不该输给随机游走——一个能看见"昨天价格"的模型，至少该追平。所以要么价格
其实没被当作输入，要么模型没学到它。**这一点值得跟论文作者确认**，它直接决定
`INCLUDE_PRICE_HISTORY` 该开还是该关。

### 注意三：汇率自身的价格——论文里有，公开代码里没有

**论文 Table 4「时序特征信息表」的第一行就是 USD/CNY 本身**（feature sample
写的是 6.8689，即 2017-02-28 的收盘价）。也就是说论文的时序特征集里**是含汇率
价格的**，模型因此有能力学到"价格几乎不变"这条规律——这也是它为什么能在
Table 7 里跑赢朴素基准。

但仓库原来那三个模型的特征集里没有它。原因见注意五：**公开代码里那三个文件
根本不是论文的实验代码**，特征集是补全时后补的，补的时候把 USD/CNY 当成目标列
排除了。

代价很大：汇率近似随机游走，"上一期价格"几乎是最强的单变量预测子，朴素基准
就是靠它拿到 0.0813 的。模型看不见价格在哪，就只能预测训练区间的均值，
**结构上不可能跑赢朴素基准**。

所以五个模型现在都有一个 `INCLUDE_PRICE_HISTORY` 开关，**默认打开**（把价格
放进输入窗口）。置为 `False` 就退回"不含价格"的口径。两条各跑一遍对比，
才知道这个缺口值多少——实测 TimesNet 从 RMSE 0.3901 降到 0.2035，差一半。

### 注意四：复现不出论文的精度（已知，不是你在哪儿弄错了）

按论文交代的超参数（隐藏维度 64、dropout 0.1、学习率 0.001、300 轮）跑，
本机实测结果：

| 模型 | 含价格历史 | 本机 RMSE | 本机 MAPE | 论文 RMSE | 论文 MAPE | 朴素基准 |
|---|---|---|---|---|---|---|
| Transformer | 否 | 0.2208 | 2.4402% | 0.0566 | 0.6532% | 0.0813 |
| Transformer | 是 | 0.3238 | 3.8719% | 同上 | 同上 | 0.0813 |
| LSTM + Attention | 是 | 0.3120 | 3.9712% | 0.0599 | 0.7205% | 0.0813 |
| RNN | 是 | 0.2716 | 3.6406% | 0.0650 | 0.8121% | 0.0813 |
| TimesNet | 否 | 0.3901 | 5.2110% | 0.0436 | 0.4874% | 0.0813 |
| TimesNet | 是 | **0.2035** | **2.6077%** | 同上 | 同上 | 0.0813 |
| TFT | 是 | 0.3721 | 4.9051% | 0.0330 | 0.3427% | 0.0853 |

这五个就是论文 Table 7 的全部模型。

两点口径说明：

- `LSTM + Attention` 和 `RNN` 的"否"那一行**没跑**——文件里的
  `INCLUDE_PRICE_HISTORY = False` 就能跑，只是没跑而已（这两个文件是补齐的，
  表里这两行的"是"才是当前默认口径）。
- TFT 的朴素基准是 0.0853 而不是 0.0813，因为它切分的是**样本列表**
  （`chronological_split`）而不是原始行（`build_sequence_dataset`），测试段起点
  略有不同。

几点如实说明：

- **五个模型都没跑赢朴素基准**，论文里它们分别赢 30%~60%。
- **TFT 是三个里最差的**，而论文里它是最好的（0.0330）。这个反差目前没有解释
  清楚。训练损失降到 0.0139、测试损失却是 0.5143（差 37 倍），预测曲线
  （`reports/tft_predictions.png`）显示：P50 **跟住了实际值的局部形状**，但整体
  系统性偏低并向下漂移——实际值在测试段从 0.75 升到 1.0（缩放后），预测却从
  0.75 降到 0.57。`TFT.py` 的 `VariableSelectionNetwork` 是**从零重写的**
  （原实现的 forward 是坏的，见文件开头的说明），所以如果重构里有残余偏差，
  最可能出在这里。**这是一条待查项，不是已知结论。**
- **Transformer 加了价格反而变差**（0.2208 → 0.3238）。先别急着下结论：这三个
  模型**都没有固定随机种子**，同一个配置跑两次结果会不一样。这个变化有可能
  只是种子噪声，要判定得先把种子固定住再各跑几次。
- TFT 那一行的朴素基准是 0.0853 而不是 0.0813，因为它切分的是**样本列表**
  （`chronological_split`）而不是原始行（`build_sequence_dataset`），测试段的
  起点略有不同。

五个模型**全都没跑赢"假设价格不变"的朴素基准**，而论文里它们都赢得很明显。
训练损失降到 0.004~0.010（说明模型在训练集上拟合得很好），测试误差却大得多
——这是典型的**过拟合**，而且训练集内的误差本身就已经和朴素基准持平了。

**原因已经查清楚了，不是调参没调到**：公开代码里那三个模型是模板、另外两个
压根没有，论文的训练脚本从来没公开。详见下面「注意五」。

不过论文有一处是**可以反推验证**的：论文报的 RMSE 与 MAPE 之比大约是个常数——

```
Transformer  0.0566 / 0.6532%  →  8.66
Transformer  0.0936 / 1.1220%  →  8.34
```

而随机游走的误差里 RMSE ≈ 1.25 × MAE（正态假设下的理论比），USD/CNY 的价格
水平约 6.9，`1.25 × 6.9 ≈ 8.6`。两者量级对得上，说明论文的目标变量是
**人民币计价的价格水平**，不是对数收益也不是差分。本项目用的口径与此一致；
但 HORIZON 具体取多少，论文确实从头到尾没写（见「注意一」）。

**这不是"论文错了"，而是公开代码缺少复现所需的实现。** 这恰好是最值得跟论文作者
当面问的一类问题，比问"这个模型怎么用"有价值得多。

### 注意五：公开代码里这三个模型是模板，不是论文的实验代码

这一条是拿到论文 PDF 之后核对出来的，可能是整个复现工作里最重要的发现。

`legacy_models/` 里三个文件的**原始版本都只造随机数据**。原文是这样的：

```python
sample_data = {
    'feature1': np.random.uniform(low=0, high=100, size=200),
    'feature2': np.random.uniform(low=50, high=150, size=200),
    'target_variable': np.sin(np.linspace(0, 10, 200)) * 50 + np.random.normal(0, 5, 200)
}
FEATURES = ['feature1', 'feature2']   # 占位
TARGET = 'target_variable'            # 占位
```

TFT 和 TimesNet 也一样（`'past_feature_1': np.random.rand(200)`、
`FEATURES = [...]`、`TARGET = '...'`）。三个文件都没有读 `Data.xlsx`；
`EPOCHS = 150`、`SEQUENCE_LENGTH = 10/30` 这些也全是模板里的示例值。

更彻底的是：**论文 Table 7 一共评了 5 个模型，公开代码里连模板都只有 3 个**
——`RNN` 和 `LSTM + Attention` 完全不存在，是从零补写的。

**结论：论文公开的是数据（`Data.xlsx` 是真的）和框架，没有公开实验代码。**
所以"复现不出 Table 7 的精度"不是调参没调到，而是论文那次实验究竟怎么跑的，
本来就没有发布出来。这同时解释了为什么论文只写了 4 个核心超参数（隐藏维度 64、
dropout 0.1、学习率 0.001、300 轮），其余——批次大小、优化器、学习率调度、
早停、HORIZON、切分比例、目标变量口径、随机种子——一个字都没提：那些细节
只存在于作者本地的训练脚本里。

本项目现在的做法是**按论文正文 + `Data.xlsx` 重新实现一套**，并把过程里每一个
需要做判断的地方都写在注释和这份文档里。补写的 `RNN.py` 和
`LSTM_Attention.py` 尤其要注意：论文只给了名字和四个超参，**网络结构是本项目
自己定的**（层数、注意力怎么算），文件开头都写明了这一点。

拿去跟论文作者讨论时，值得问的不是"为什么复现不出来"，而是"能不能要一份实验代码
或配置"，或者至少确认上面那几个缺失的参数。

### 关于 TFT 为什么慢

TFT 的变量选择网络给**每一个**输入变量各配了一个 GRN（门控残差网络）。历史
协变量有 33 个，所以每前向一次就要跑 33 个 GRN，在 CPU 上约 4 秒一轮，
300 轮就是 20 多分钟。这是标准 TFT 的结构，不是写错了。

想快点跑通就把 `HORIZON` 或 `SEQUENCE_LENGTH` 调小，或者临时把训练轮数
从 300 降到 50（只影响精度，不影响能不能跑通）。

## 七、DA 的复现结果

DA 是论文最核心的创新点，前面讲了它的三步机制，这里给跑出来的结果。

```powershell
.\venv\Scripts\python.exe scripts\run_da_selection.py
```

32 个候选特征全部评完（有缓存之后几秒钟），结果写到 `reports/da_selection.json`，
里面每个特征都能看到三个维度的分数、LLM 给的理由、以及检索到的证据出处。

### 和论文 Table 8 的对照

论文最终选中 4 个，本次选中 10 个，**交集 3 个**：

```
论文选中：Negative_Events、China_FX_Reserves、WTI_Futures_Price、US_1Y_Treasury_Yield
本次选中：Negative_Events、China_FX_Reserves、WTI_Futures_Price（+ 另外 7 个）
论文选了本次没选：US_1Y_Treasury_Yield（本次 76.0，差 4 分）
```

排序结构是对得上的：论文 Table 6 排第一的 `Negative events`，本次也是第一
（92.0）；论文 Table 6 里垫底、只有 8 分的 `US Removal from Currency
Manipulator List`，本次也是最后一名（22.0）。

### 分数整体比论文"扁"（这条值得注意）

论文 Table 6 挑出来展示的五档分数是 **100 / 92 / 90 / 80 / 8**——除最后一名外
都挤在 80 分以上，第四名之后就断崖。本次的分布**扁得多**：

```
92.0  Negative_Events、Negative_Events_from_the_US
84.0  USD_Index、China_FX_Reserves、China_Tariff_Increases_on_the_US
80.0  WTI_Futures_Price、US_Tariff_Increases_on_China、US、China、
      US_Litigation_or_Investigation_against_China
```

**32 个特征里有 5 个恰好落在 80.0 这条线上。** 原因不难推：80 分换算成原始分
正好是 4.0，而模型很爱给 (相关性 4.0、支持度 4.0、实用性 4.0) 这样整齐的分
——`0.2×4 + 0.4×4 + 0.4×4 = 4.0`，一分不多一分不少。于是"采纳与否"变成了一件
很脆的事：某个特征的支持度从 4.0 落到 3.5，总分就从 80 掉到 72，直接出局。

论文那边没有这个问题，说明**它的知识库对不同特征的证据覆盖差别很大**——证据足的
给满分，证据少的（比如那个象征性政策）直接掉到 8 分。而本项目的知识库是四份
自行整理的机制说明，覆盖相对均匀，所以分数挤在一起。

**这不是 bug，是知识库规模的直接后果。** 想让 DA 更有区分度，就往
`data/knowledge_base/papers/` 里放真正的文献（README 里写了怎么加），覆盖差的
特征分数自然会掉下去。

### 顺带一提：换归一化方式会改变结论

`--normalization batch` 切到论文公式 (2) 的字面写法之后，分数会被拉伸到
`[0, 100]` 的满量程（永远有一个 100、一个 0），恰好落在 80 分线上的那几个
特征结果会不一样。**所以"选了几个特征"这件事对归一化方式很敏感**，这也是
为什么论文公式 (2) 和 Table 6 对不上这件事值得找作者确认。

### 对照组：传统特征工程基线（论文 §4.4）

论文 Table 8 把 DA 选的特征和「传统特征工程」选的特征做了对照，Table 9 又把
这两套特征分别喂给五个模型比精度。**对照组要自己算出来才谈得上"比较"**，
所以补了 `src/core/traditional_baseline.py`：

```powershell
.\venv\Scripts\python.exe scripts\verify_traditional_baseline.py
```

几秒钟跑完，不联网、不用密钥。结果是：

| 环节 | 论文 Table 8 | 本次 | 结论 |
|---|---|---|---|
| 时序线：Pearson 相关 + 0.7 去重 | `USD_Index`、`CN_1Y_GovBond_Yield` | 同左 | **完全一致** |
| 事件线：XGBoost 重要度 + 均值阈值 | 22 项里留 2 项 | 22 项里留 6 项 | 论文的 2 项是我们的前两名 |

**论文的那 4 个特征全部出现在算出来的集合里**，多出来的 4 个是论文用「信息重叠」
那一步剔除的——那一步论文只写了一句"Sino-US dialogue 被 positive events 包含、
US restrictions 被 negative events 包含"，没有给出可执行规则。

#### 顺带发现的第二处"公式和结果对不上"

论文 Eq. (4) 写的是"特征当分裂变量的**次数**"，字面对应 XGBoost 的
`importance_type="weight"`。但按它算，论文 Fig. 6 排第 3 的 `Negative_Events`
会掉到**第 20 名**：

| 特征 | 论文 Fig. 6 | `weight`（公式字面） | `gain`（XGBoost 默认） |
|---|---|---|---|
| Positive events | 第 1 | 第 5 | 第 2 |
| US restrictions on Chinese enterprises | 第 2 | 第 2 | 第 5 |
| Negative events | 第 3 | **第 20** | **第 1** |
| China tariff increases on the US | 第 4 | 第 4 | 第 4 |

换成 `gain` 之后，论文最终保留的两个特征正好是前两名。所以模块默认用 `gain`，
想复现公式的字面写法就传 `importance_type="weight"`。

**这和公式 (2) 与 Table 6 对不上是同一类问题**：正文里的算式和图表里的数字
矛盾，像是最后跑实验时换了口径但正文没同步。两条都值得一起问作者。

```
【模型解读】这次经过 Optuna 在 10 组超参中调参，最终选中的是 ridge 模型……
```

### 切分层次（这条很重要）

Optuna 需要一个"哪组超参更好"的判据。**不能拿最终测试集当判据**——那等于用
测试集选模型，报出来的误差是乐观偏差。实际的做法是切三层：

```
全部数据
  └─ train（前 80%）
  │    ├─ fit 段（前 80%）        ← Optuna 在这里拟合
  │    └─ 验证段（后 20%）        ← Optuna 只在这里比较超参
  └─ test（后 20%）               ← 从头到尾只用来算最终指标，算一次
```

选完超参后用**全部 train** 重新拟合，最后才碰 test。这条约束是结构上保证的
——`optimize_hyperparameters()` 的签名里根本没有测试集参数。

### 搜索的四类模型，以及一处和论文对不上的地方

搜的是 Ridge、随机森林、梯度提升、小 MLP 四类**表格模型**。

**这里和论文是不一致的，但不是"论文没说清楚"——论文说清楚了。** §3.3.4 原文是
Optuna 用于 "forecasting models such as recurrent neural networks (RNNs),
LSTMs, and Transformers"，也就是对那类**深度模型**调参，不是表格模型。

本项目之所以没照做：那类模型在单次请求的数据量（几百到两千行）上站不住脚，
而 `legacy_models/` 里已经有论文真正用的那五个深度模型了。所以这块是"按论文的
意图补了一个能跑的版本"，口径和论文不同，对照数字时要留意。

（早先这里写的是"论文没说对哪个模型调"，那是拿到 PDF 之前的推测；PDF 到手后
发现论文其实写了。这一条已经更正。）

## 九、PA2 的复现：新闻是怎么变成事件特征的

`Data.xlsx` 里两个 sheet 是上下游关系：

- `Sheet1` —— 445 条中美贸易新闻，每条带中文的**事件类型 / 来源 / 情感**标签，
  多标签用 `/` 分隔；
- `Data` —— 1944 行的日频表，其中 25 列是 0/1 的事件哑变量。

中间那步"按天折叠"公开代码里没有。跑这个脚本可以看复现结果：

```powershell
.\venv\Scripts\python.exe scripts\verify_pa2_aggregation.py
```

脚本会跑三种"新闻落在非交易日时怎么办"的口径，然后和 `Data` sheet 逐列对照。
实测结果：

| 日期口径 | 完全一致的列 | 平均交并比 |
|---|---|---|
| 落到之后最近的交易日（`next`） | **7 / 25** | **0.948** |
| 只保留正好是交易日的（`exact`） | 4 / 25 | 0.862 |
| 落到之前最近的交易日（`previous`） | 4 / 25 | 0.784 |

`next` 口径下多数列只差 1~4 天（`Negative_Events` 248 vs 248、
`US` 254 vs 254、`Sino_US` 115 vs 115）。

**结论：新闻是落到"之后最近的交易日"的**，聚合规则也和列名语义对得上。
剩下的差异是因为 `Sheet1` 只是语料的一个子集——`Data` 那一侧覆盖的新闻更多，
所以是"`Data` 有、`Sheet1` 没有"的情况为主。

这个脚本不需要 API 密钥，不联网，几秒钟跑完，适合拿去给论文作者看。

### 429 这个数到底是什么（这条推翻了早先的一个疑问）

论文 §4.2 说 PA1 按中国 / 美国 / 中美等关键词**采集了 1030 条**政策与新闻事件，
PA2 剔除军事、地缘冲突、第三方国家等与双边贸易无关的内容后**剩下 429 条**。
而 `Data.xlsx` 的 `Sheet1` 里是 **445 条**新闻，乍看对不上。

实测下来结论是：**429 不是新闻条数，是「有事件发生的交易日数」。** 把 `Data`
sheet 的 25 个事件列按行求或，恰好有 **429 天**不为零，和论文的数字严丝合缝。

再核对 445 条这一侧：按「落到之后最近的交易日」折叠，445 条新闻覆盖
**426 个**交易日——只比 429 少 **3 天**（99.3%）。

所以两边的口径是自洽的：

```
Sheet1 的 445 条新闻  ──按天折叠──▶  426 个事件日
Data sheet 的事件列   ──────────▶  429 个事件日     差 3 天
```

`Sheet1` 是 `Data` 所用语料的一个**近乎完整的快照**，漏了 3 天的事件。
**这条不是"对不上"，是已经对上了**——早先按"445 条 vs 429 个事件"来怀疑口径
不一致，是把两个不同的量当成同一个了。

## 十、底座大模型：论文用 R1，本项目的默认值是 chat

论文 §4.1 写的是 FX-Agents "leverages the DeepSeek-R1 (671B) model as the base
LLM"。本项目默认用的却是 `deepseek-chat`，原因不是省事，是 API 能力的硬约束，
而且是实测出来的。

DA 给特征打分要求**结构化输出**（三个 0-5 的分数 + 理由），走的是
`with_structured_output`。DeepSeek 拒绝默认的 json_schema 模式，所以可用的路
只有两条：`function_calling` 和 `json_mode`。实测四个组合：

| 模型 | 结构化输出方式 | 结果 |
|---|---|---|
| `deepseek-chat` | `function_calling` | 通过 |
| `deepseek-chat` | `json_mode` | 通过 |
| **`deepseek-reasoner`（R1）** | `function_calling` | **400：Thinking mode does not support this tool_choice** |
| `deepseek-reasoner`（R1） | `json_mode` | 通过 |

R1 的思考模式不支持 `tool_choice`，而 `function_calling` 正是靠它工作的。所以
`src/services/deepseek_llm_service.py` 现在**按模型名自动选实现方式**：思考型
模型走 `json_mode`，其余走更严格的 `function_calling`。

**想按论文口径跑，在 `.env` 里加一行就行：**

```
DEEPSEEK_MODEL="deepseek-reasoner"
```

一个配套的坑已经堵上：DA 的磁盘缓存键里现在**带着模型名**。不带的话，换模型之后
DA 会直接命中上一个模型留下的分数——看起来"换了模型结果一样"，实际上根本没调
新模型。默认模型的命名空间是空串，所以项目里已有那批缓存不会作废。

## 十一、关于诚实性

这个项目里有几处刻意"不好看"但必须保留的地方：

1. **模型常常跑不赢朴素基准。** 汇率的一步预测本来就极难，一个只会说
   "明天和今天一样"的模型经常打败复杂模型。程序会如实打印这个对比，
   不会掩饰。这不是 bug。用 `--optimize` 时实测 MAE 0.01089 对基准 0.01092
   ——只赢了 0.2%，程序照样会打印"优势幅度很小"。
2. **知识库里的说明是项目自行整理的**，不是学术引用。这样标注是为了避免
   拿论文自己的结论去论证论文自己的特征选择（那是循环论证）。
3. **数据口径存疑的地方会标出来**，比如 `CN_CPI_MoM` 论文标为环比，
   但数值量级看起来像同比。处理方式是沿用论文命名 + 注明存疑，
   不替原作者改口径。
4. **原代码里"看着像 bug 其实是设计"的地方保留原样**，只加注释说明简化在哪。
   比如 TimesNet 的频域层没有共轭对称约束、TFT 的注意力没有因果掩码，
   改了会破坏和论文的可比性。
5. **选不到特征、检索不到证据、算不出 SHAP、模型打不过基准**，
   每一种情况都会走降级路径并如实说明，不会静默吞掉。
